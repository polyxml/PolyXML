## Summary of New Issues Filed in the 50-Item Audit

1. **[#128: [Codegen] Preserve xs:anyAttribute wildcards in generated models and codecs](https://github.com/polyxml/PolyXML/issues/128)**
   `xs:anyAttribute` is parsed by PolyXML but dropped entirely from generated Python, Go, and C# models, causing silent data loss for any foreign or extension attributes in incoming XML.
2. **[#129: [Rust Codegen] Sanitize module identifiers in mod.rs when schema filename starts with a digit](https://github.com/polyxml/PolyXML/issues/129)**
   When an XSD file name begins with a number (e.g. `17_tree.xsd` or `3gpp_spec.xsd`), PolyXML emits invalid Rust code (`pub mod 17_tree;`) in `mod.rs`, which `rustc` fails to compile.
3. **[#130: [Python Codegen] Correctly initialize simpleContent element defaults to typed objects](https://github.com/polyxml/PolyXML/issues/130)**
   When an element has an `xs:simpleContent` complexType and an XSD `default`, Python emits `field(default="...")` with a string literal, resulting in wrong runtime types and empty XML serialization (`<flag></flag>`).
4. **[#131: [Schema Validator] Enforce Unique Particle Attribution (UPA) to reject ambiguous content models](https://github.com/polyxml/PolyXML/issues/131)**
   `polyxml validate` accepts non-deterministic content models that violate W3C UPA, whereas standards-compliant validators (`lxml.etree.XMLSchema`) correctly reject them.

## Notable PolyXML Competitive Advantages Confirmed

- **Go XMLName conflict resolution**: PolyXML cleanly disambiguates an element named `XMLName` into `XMLName_2` with `xml:"XMLName,omitempty"`, whereas `xuri/xgen #83` breaks.
- **Element and attribute name collision**: Sibling element and attribute with the exact same name are automatically disambiguated across Python, Go, and C#, preserving both values during round-tripping (unlike `xuri/xgen #86`).
- **Multiple `xs:pattern` facets**: PolyXML correctly compiles multiple pattern facets into a regex union `(?:(pat1)|(pat2))` conforming to W3C OR semantics, avoiding the AND/OR confusion in `Bergmann89/xsd-parser #253`.
- **Lenient sequence deserialization**: Unknown elements inside `<xs:sequence>` are skipped cleanly by Python and Rust parsers without throwing unexpected token errors (unlike `Bergmann89/xsd-parser #293`).
- **Case-insensitive enum variant collisions**: PolyXML numbers colliding variants (`Test`, `Test2`, `Test3`) while preserving exact string parsing and serialization (unlike `lumeohq/xsd-parser-rs #172`).
